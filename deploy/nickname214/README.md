* Validates exact systemd User/WorkingDirectory/EnvironmentFiles/ExecStart contract, Linux x86_64 and Node 22.23.4. Requires installed root-owned persistent storage verifier and ENV_ONLY for both releases. LINK is intentionally unsupported for this specific known installation.
* Rejects any Nginx config referencing `/opt/xamuko/deploy/current`: backend-only releases cannot satisfy a versioned frontend. Tests Nginx and compares public HTML before/after without rewriting frontend or reloading Nginx. A changing HTML page fails safely; review an alternative stable frontend fingerprint if necessary.
* Candidate health uses an isolated systemd network namespace, fake DB and test-only credentials, strict read-only filesystem and no persistent-storage access. It cannot contact production DB, S3, SMTP or OAuth. Health only; no private records or public-businesses request during candidate smoke.

Post-activation checks actual process cwd, structured health, unchanged frontend and public businesses HTTP. VERIFIED is written only after success. Any activation exception, SIGINT or SIGTERM attempts recovery to the captured `deb9c284`, not existing `previous=4bd425...`. A recovery failure preserves candidate evidence and returns failure. SIGKILL, power loss and host failure need operator recovery; no software trap can guarantee recovery for those cases.
* Updates `previous` only on success. Never prunes retained releases. No standalone arbitrary rollback interface. Does not create READY, SSM, IAM, S3 objects, accounts or secrets.
